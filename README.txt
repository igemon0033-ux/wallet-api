========================================================================
                 FASTAPI USER WALLETS REST API
========================================================================

Высокопроизводительное асинхронное REST API приложение для управления 
балансом пользовательских кошельков, спроектированное для работы под 
высокой параллельной нагрузкой.

------------------------------------------------------------------------
1. ТЕХНОЛОГИЧЕСКИЙ СТЕК
------------------------------------------------------------------------
* Python 3.11
* FastAPI -- асинхронный веб-фреймворк с автогенерацией документации (Swagger).
* PostgreSQL -- реляционная СУБД для обеспечения транзакционности (ACID).
* SQLAlchemy 2.0 (Async) + asyncpg -- асинхронный ORM.
* Alembic -- автоматическое применение миграций при запуске.
* Pydantic v2 -- строгая валидация типов и ограничение точности денежных сумм.
* Pytest & HTTPX -- тесты, включая симуляцию конкурентных запросов.
* Docker & Docker Compose -- оркестрация всей системы одной командой.

------------------------------------------------------------------------
2. БЕЗОПАСНОСТЬ И КОНКУРЕНТНОСТЬ (CONCURRENCY SAFETY)
------------------------------------------------------------------------
Основное требование задачи -- корректная обработка параллельных запросов \nна изменение баланса одного и того же кошелька. \n\nДля предотвращения рассинхронизации баланса (race conditions, lost updates, \ndouble-spending) реализована стратегия пессимистичной блокировки строк на \nуровне базы данных (Pessimistic Locking):\n* При обработке операции DEPOSIT или WITHDRAW, в рамках транзакции выполняется \n  запрос с оператором .with_for_update() (генерирует SQL SELECT ... FOR UPDATE).\n* Это блокирует строку кошелька в PostgreSQL для записи. Любой другой параллельный \n  запрос к этому же кошельку заблокируется и будет ожидать завершения \n  (commit или rollback) первой транзакции.\n* Данный подход обеспечивает строгую последовательность обновлений и предотвращает \n  баланс ниже нуля даже при множестве одновременных списаний.\n\nПримечание для тестирования: SQLite не поддерживает полноценный row-level FOR UPDATE \nв режиме параллельных сессий. Чтобы юнит-тесты на SQLite проходили успешно и \nверифицировали логику конкурентности локально, в сервисный слой встроен гибридный \nмеханизм: для SQLite используется asyncio.Lock по UUID кошелька, а для PostgreSQL -- \nнативные блокировки СУБД.\n\n------------------------------------------------------------------------\n3. СТРУКТУРА ПРОЕКТА\n------------------------------------------------------------------------\n├── Dockerfile              # Docker-инструкция для сборки FastAPI приложения\n├── README.txt              # Документация проекта (этот файл)\n├── alembic.ini             # Конфигурация Alembic\n├── app\n│   ├── __init__.py\n│   ├── config.py           # Конфигурация приложения на Pydantic Settings\n│   ├── database.py         # Подключение к БД и генератор сессий\n│   ├── main.py             # Точка входа FastAPI, обработчики ошибок и эндпоинты\n│   ├── migrations          # Каталог миграций Alembic\n│   │   ├── env.py          # Конфигурация окружения миграций\n│   │   ├── script.py.mako\n│   │   └── versions        # Файлы версий миграций\n│   ├── models.py           # SQLAlchemy-модель Wallet\n│   ├── schemas.py          # Pydantic-схемы валидации данных\n│   ├── services.py         # Бизнес-логика и конкурентные блокировки\n│   └── tests               # Модульные и интеграционные тесты\n│       ├── __init__.py\n│       ├── conftest.py     # Фикстуры для тестирования (in-memory SQLite)\n│       └── test_wallets.py # Тест-кейсы (включая стресс-тест конкурентности)\n├── docker-compose.yml      # Оркестрация FastAPI и PostgreSQL контейнеров\n├── entrypoint.sh           # Скрипт проверки готовности БД и авто-миграций\n├── pytest.ini              # Настройки pytest (asyncio_mode = auto)\n└── requirements.txt        # Список зависимостей\n\n------------------------------------------------------------------------\n4. БЫСТРЫЙ ЗАПУСК (DOCKER COMPOSE)\n------------------------------------------------------------------------\nЗапуск всей инфраструктуры (FastAPI приложение, база данных PostgreSQL, \nприменение миграций) выполняется одной командой в терминале:\n\ndocker compose up --build\n\nПосле успешного запуска:\n* API будет доступно по адресу: http://localhost:8000\n* Интерактивная документация (Swagger UI): http://localhost:8000/docs\n* Альтернативная документация (ReDoc): http://localhost:8000/redoc\n\n------------------------------------------------------------------------\n5. API ЭНДПОИНТЫ\n------------------------------------------------------------------------\n\nA. Создание кошелька (Вспомогательный эндпоинт)\n* Метод: POST\n* Путь: /api/v1/wallets\n* Описание: Создает новый пустой кошелек с балансом 0.00.\n* Пример ответа (201 Created):\n  {\n    \"id\": \"e67417e2-45e3-47a3-ba09-847ef25faee8\",\n    \"balance\": 0.00\n  }\n\nB. Изменение баланса кошелька\n* Метод: POST\n* Путь: /api/v1/wallets/<WALLET_UUID>/operation\n* Тело запроса:\n  {\n    \"operation_type\": \"DEPOSIT\", // или \"WITHDRAW\"\n    \"amount\": 1000.50\n  }\n* Валидация:\n  * amount должен быть строго больше нуля (> 0).\n  * amount должен содержать не более 2 знаков после запятой (копейки). При неверном \n    формате возвращается ошибка 422 Unprocessable Entity.\n* Обработка ошибок:\n  * Если кошелек не найден -> 404 Not Found.\n  * Если тип операции WITHDRAW и баланс недостаточен -> 400 Bad Request с сообщением \n    {\"detail\": \"Insufficient funds\"}.\n\nC. Получение баланса кошелька\n* Метод: GET\n* Путь: /api/v1/wallets/<WALLET_UUID>\n* Описание: Возвращает ID кошелька и его текущий баланс.\n* Пример ответа (200 OK):\n  {\n    \"id\": \"e67417e2-45e3-47a3-ba09-847ef25faee8\",\n    \"balance\": 1000.50\n  }\n\n------------------------------------------------------------------------\n6. ЗАПУСК ТЕСТОВ\n------------------------------------------------------------------------\nТесты покрывают все сценарии валидации входных данных, негативные кейсы \n(списание при нехватке средств, несуществующие UUID) и стресс-тест на \nконкурентность (10 одновременных транзакций к одному кошельку).\n\nДля запуска тестов локально:\n1. Откройте Терминал на вашем Mac.\n2. Перейдите в папку с проектом.\n3. Активируйте виртуальное окружение:\n   source .venv/bin/activate\n4. Запустите тесты командой:\n   pytest -v\n"
